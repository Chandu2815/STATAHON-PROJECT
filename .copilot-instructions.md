## Architecture Patterns

### Node.js Backend (Express.js)
```
Route → Controller → Service → Model → Database
```
**Key Principles:**
- Express Router for modular routing
- MVC architecture strictly followed
- Async/await for all operations
- Connection pooling with pg library
- Structured JSON responses with metadata
- Centralized error handler middleware
- REST naming conventions (GET /users, POST /datasets, etc.)

### FastAPI Backend (Python)
```
APIRouter → Service Layer → Pydantic Schema → SQLAlchemy ORM → Database
```
**Key Principles:**
- APIRouter for modular route organization
- Dependency injection for session management
- Async endpoints for better performance
- Pydantic models for request/response validation
- SQLAlchemy session factory pattern
- HTTPException for error handling
- Scalable service architecture

### Database Layer
```
PostgreSQL ← Connection Pool ← Query Helpers ← Service Layer
```
**Key Principles:**
- Use connection pooling (pool_size=10, max_overflow=20)
- Parameterized queries only (no string concatenation)
- Input sanitization at service layer
- Query optimization with indexes
- Reusable query helper functions

## Authentication & Security

### Node.js Authentication Flow
1. User submits email/password to `POST /api/auth/login`
2. Controller calls `authService.validateUser()`
3. Service queries users table with parameterized query
4. bcrypt compares hashed password
5. JWT token generated with secret key
6. Return `{ token, expiresIn, user }`

### JWT Middleware
```javascript
// middleware/auth.js
const verifyToken = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ error: 'No token' });
  
  jwt.verify(token, process.env.SECRET_KEY, (err, decoded) => {
    if (err) return res.status(401).json({ error: 'Invalid token' });
    req.user = decoded;
    next();
  });
};
```

## Performance Optimization Rules

1. **Database Queries**
   - Use connection pooling (already configured)
   - Add indexes on filter columns
   - Limit result sets with pagination
   - Avoid `SELECT *` - specify columns needed

2. **Caching Strategy**
   - Cache hierarchical dataset list (updates rarely)
   - Cache dataset metadata (TTL: 1 hour)
   - Invalidate on schema changes

3. **API Response Optimization**
   - Implement pagination for large result sets
   - Use field selection/projection
   - Minimize nested objects in response
   - Compress responses (gzip)

4. **Async Operations**
   - All I/O operations must be async
   - Use connection pooling
   - Implement request timeouts
   - Use batch queries where possible

## Error Handling Guidelines

### Centralized Error Handler (Node.js)
```javascript
// middleware/errorHandler.js
app.use((err, req, res, next) => {
  const status = err.status || 500;
  const message = err.message || 'Internal Server Error';
  
  res.status(status).json({
    success: false,
    error: message,
    code: err.code,
    meta: { statusCode: status }
  });
});
```

### Exception Handling (FastAPI)
```python
# Use HTTPException for known errors
from fastapi import HTTPException

@app.exception_handler(HTTPException)
async def http_exception_handler(request, exc):
    return {
        "success": False,
        "error": exc.detail,
        "meta": {"statusCode": exc.status_code}
    }
```

### Error Codes
- `VALIDATION_ERROR` - Invalid request payload
- `UNAUTHORIZED` - Missing/invalid token
- `FORBIDDEN` - Insufficient permissions
- `NOT_FOUND` - Resource not found
- `CONFLICT` - Resource already exists
- `DATABASE_ERROR` - Database operation failed
- `INTERNAL_ERROR` - Unexpected server error
